# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**self-evolution** is a Claude Code plugin that automatically extracts reusable workflows from conversations and converts them into skills. It runs in companion-mode (background `claude -p` process) and enforces hard-gated security scanning before any skill writes.

## Build & Test Commands

```bash
npm run build       # esbuild bundle → dist/runtime.mjs
npm test            # vitest run (all tests)
npm run test:watch  # vitest with watch mode
```

Running a single test:
```bash
npx vitest run src/__tests__/security-scan.test.ts
```

All tests live in `src/__tests__/` (co-located pattern, not next to source files). Vitest runs in single-fork mode (`vitest.config.ts`).

**Entry point**: `dist/runtime.mjs` (generated by esbuild from `src/runtime.ts`)

## Architecture

```
src/
├── runtime.ts          # Command router — all CLI commands pass through here
├── types.ts            # Shared TypeScript interfaces (State, Security, Transcript, Platform, Spawn, Config)
├── commands/           # 12 command handlers
└── lib/
    ├── adapter.ts      # Platform detection + adapter factory (getAdapter())
    ├── adapters/       # Platform-specific implementations (claude-code.ts, codex.ts, cursor.ts)
    ├── config.ts       # Config loading, env var overrides, schema validation (CONFIG_SCHEMA, ENV_VAR_MAP)
    ├── logger.ts       # JSONL session logger
    ├── security.ts     # Pattern-based content scanner (injection, dangerous bash, secrets, base64)
    ├── spawner.ts      # Companion process spawning + prompt variant selection
    ├── state.ts        # State persistence (sessions, jobs)
    └── transcript.ts   # Transcript parsing + summary

hooks/                  # Hook definitions (hooks.json, hooks.codex.json, hooks.cursor.json)
agents/skill-reviewer.md  # 8-step reviewer pipeline (context → rationale → scan → generate → validate → verify → log → output)
commands/              # 4 user-facing slash commands (/evolve-review, /evolve-status, /evolve-config, /evolve-delete-skill)
prompts/               # 4 companion prompt templates (review-prompt.md, -skill.md, -update.md, -combined.md)
skills/evolve-skill-writer/  # Meta-skill for SKILL.md generation
```

### Runtime Commands (all routed through `runtime.mjs`)

| Command | Trigger | Purpose |
|---------|---------|---------|
| `session-start` | SessionStart hook | Diagnostic log on startup |
| `post-tool-use` | PostToolUse hook | Increment tool call counter, set `pending_review` at nudge threshold |
| `stop-gate` | Stop hook | Consume pending_review, spawn detached companion process |
| `security-scan` | Called by reviewer before Write | Scan path + content, return `{allowed, reason?}` |
| `review-context` | Called by companion agent | Return transcript summary + existing skills list |
| `log-decision` | Called by reviewer after decision | Log CREATED/UPDATED/SKIPPED to JSONL + stats |
| `status` | `/evolve-status` | Show sessions and job history |
| `validate-skill` | Called by reviewer after Write | Validate skill structure, return `{valid, errors?}` |
| `verify-skill` | Called by reviewer after Write/Edit | Verify skill content, return `{verified, errors?}` |
| `delete-skill` | `/evolve-delete-skill` | Delete a skill by name |
| `config-get` | `/evolve-config` | Read config value |
| `config-set` | `/evolve-config` | Write/reset config value |

### Hook Flow (Auto Mode)

```
PostToolUse → increment counter → set pending_review at threshold
Stop hook → consume pending_review → spawn detached `claude -p` companion → reviewer pipeline
```

The `post-tool-use` and `stop-gate` commands read hook input from **stdin** (not CLI args). All other commands use CLI args.

### Companion Prompt Variant Selection

The spawner selects a prompt template based on transcript/skill overlap:
- **skill** (creation focus): no overlap between existing skills and transcript
- **update** (update focus): keyword overlap detected
- **combined** (both): empty or missing transcript

### Multi-Platform Support

Three platforms via a `PlatformAdapter` interface (`src/lib/adapter.ts` + `src/lib/adapters/`):

| Platform | Manifest | Hooks | Companion CLI | Skill Dirs |
|----------|----------|-------|---------------|------------|
| Claude Code | `.claude-plugin/` | `hooks/hooks.json` | `claude -p` | `~/.claude/skills/` |
| Codex | `.codex-plugin/` | `hooks/hooks.codex.json` | `codex exec` | `~/.agents/skills/`, `~/.claude/skills/` |
| Cursor | `.cursor-plugin/` | `hooks/hooks.cursor.json` | `agent -p` | `~/.cursor/skills/`, `~/.claude/skills/`, `~/.agents/skills/` |

Platform detection priority: `CLAUDE_PLUGIN_ROOT` → `CODEX_SESSION_ID` → `CURSOR_PROJECT_DIR` → manifest directory check → default claude-code.

All platforms share the same `dist/runtime.mjs` bundle. Use `scripts/package.sh` to create platform-specific tarballs in `dist-packages/`.

### Key Design Decisions

- **TypeScript + esbuild**: Single-file bundle (`dist/runtime.mjs`) — no shell script dependencies
- **Pure command hooks**: All hooks use `type: "command"`, no in-session agents blocking the main session
- **Companion mode**: Stop hook spawns `claude -p` as detached background process
- **Security at write-time**: Scanning happens inside the reviewer agent flow, not via global PreToolUse hook
- **Security scan is mandatory**: Reviewer MUST run security-scan before Write, validate-skill after Write, verify-skill after Write/Edit (see `agents/skill-reviewer.md`)

## Security Model

The `security-scan` command enforces:
- **Path whitelist**: Only `~/.claude/skills/<name>/SKILL.md` is writable (and platform-specific skill dirs)
- **Content scanning**: Prompt injection, dangerous bash, secrets, base64 attacks, binary file extensions, size limits
- **Per-file and total size limits**: `max_skill_file_size` (256KB default), `max_skill_total_size` (1MB default)
- **File count limit**: `max_files_per_skill` (50 default)

## Configuration

Config is loaded from `config.json` or `config.default.json` (checked in pluginData then pluginRoot), with env var overrides using `SELF_EVOLUTION_` prefix. Key settings:

| Setting | Default | Env Var |
|---------|---------|---------|
| `nudge_interval` | 10 | `SELF_EVOLUTION_NUDGE_INTERVAL` |
| `review_model` | "sonnet" | `SELF_EVOLUTION_REVIEW_MODEL` |
| `platform` | "auto" | `SELF_EVOLUTION_PLATFORM` |
| `log_level` | "info" | `SELF_EVOLUTION_LOG_LEVEL` |
| `review_max_turns` | 8 | `SELF_EVOLUTION_REVIEW_MAX_TURNS` |
| `max_skill_file_size` | 262144 | `SELF_EVOLUTION_MAX_SKILL_FILE_SIZE` |

Full schema with validation rules in `src/lib/config.ts` (`CONFIG_SCHEMA`).
